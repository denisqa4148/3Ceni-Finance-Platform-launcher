# Постоянная авторизация v172

Базовая версия: Finance v171, launcher v29.

## Установленная причина

Лог после нового запуска показывает создание обычной авторизованной
Streamlit-сессии, но не показывает ни восстановления cookie, ни получения
одноразового билета. На проверенных браузерах обязательный путь через
embedded-cookie/HTTP-обмен не доходит до Python-сессии.

## Решение

- Добавлен скрытый двусторонний Streamlit-компонент авторизации.
- После входа компонент синхронно сохраняет подписанный токен в origin-local
  storage и в first-party storage фирменного launcher.
- При новом открытии компонент возвращает токен прямо в Python через штатное
  значение Streamlit-компонента, без cookie, URL и отдельного HTTP-запроса.
- Python заново проверяет HMAC-подпись, срок действия, активность пользователя
  и fingerprint текущего пароля. Доверия к данным браузера нет.
- Cookie и одноразовый билет сохранены только как дополнительные резервные
  пути совместимости.
- Launcher v30 загружает Finance немедленно; восстановление выполняет новый
  компонент, поэтому не возникает ожидания HTTP timeout.

## Изменённые файлы

- `src/auth.py`
- `src/components/auth_bridge/index.html` (новый)
- `tests/test_pwa_auth_bridge_v170.py`
- launcher: `index.html`, `sw.js`

## Установка

1. В Finance заменить `src/auth.py`.
2. Создать каталог `src/components/auth_bridge` и добавить в него `index.html`.
3. Тестовый файл можно заменить вместе с патчем.
4. Перезапустить Streamlit и дождаться полной загрузки.
5. После этого заменить `index.html` и `sw.js` в launcher.
6. Войти один раз. Последующие reload, закрытие/открытие браузера и запуск с
   фирменной иконки должны восстанавливать вход до 14 дней.

После смены пароля, отключения пользователя или явного выхода сохранённый
токен перестаёт восстанавливать доступ.
