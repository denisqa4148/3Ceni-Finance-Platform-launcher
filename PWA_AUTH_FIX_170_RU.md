# Исправление PWA-авторизации v170

База: предоставленный пользователем архив `3Ceni-Finance-Platform-main-163.zip`,
содержащий security-обновления v169.1.

## Первопричина

Установленная PWA работает на origin `denisqa4148.github.io` и показывает
Streamlit во вложенном iframe. Safari/WebKit не гарантирует постоянство cookie
и `localStorage` стороннего Streamlit-origin. Лаунчер v27 уже умел хранить
подписанный токен как first-party данные, но Finance после security-патча
перестал отправлять сообщение `3ceni-auth-token-v19`. Поэтому после обновления
у лаунчера не было токена для восстановления входа.

## Решение

- Finance отправляет подписанный токен только точному origin из
  `PWA_LAUNCHER_ORIGINS`.
- Лаунчер хранит токен в своём first-party `localStorage`.
- После обновления Finance запрашивает токен через проверенный `postMessage`.
- Токен передаётся серверу POST-запросом и обменивается на одноразовый билет.
- `appTarget()` больше не добавляет `_session` в URL.
- Service worker v28 принудительно заменяет закэшированный лаунчер v27.

## Установка

1. В основном репозитории Finance заменить `src/auth.py` и `src/ui/layout.py`,
   добавить тест `tests/test_pwa_auth_bridge_v170.py`, затем дождаться перезапуска
   Streamlit Cloud.
2. В репозитории `3Ceni-Finance-Platform-launcher` заменить `index.html` и
   `sw.js`, затем дождаться публикации GitHub Pages.
3. Полностью закрыть установленную PWA и открыть снова. Первый вход после
   обновления выполняется вручную один раз. Следующие обновления страницы должны
   восстанавливать сессию без пароля.

## Откат

Вернуть четыре заменённых рабочих файла из предыдущих версий двух репозиториев.
Финансовые и пользовательские данные этим патчем не изменяются.
